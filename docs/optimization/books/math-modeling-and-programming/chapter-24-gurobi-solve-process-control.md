# 第 24 章 基本求解进程控制方法

> 根据《第 24 章 基本求解进程控制方法》整理，原文页码为 314-324。

## 1. 本章知识框架

本章介绍如何通过 Gurobi 参数控制 MIP 模型的求解过程，核心内容包括：

1. 设置求解终止条件；
2. 设置预处理算法；
3. 设置割平面算法；
4. 设置启发式算法；
5. 设置整体优化策略、根节点求解方法和变量分支策略。

对于最小化问题，可以把各类方法的作用概括为：

| 方法       | 主要作用           | 对求解过程的影响                               |
| ---------- | ------------------ | ---------------------------------------------- |
| 终止条件   | 决定何时停止求解   | 在时间、工作量、Gap、节点数等达到阈值时终止    |
| 预处理     | 精简模型结构       | 删除冗余行列、缩小系数范围，降低后续求解难度   |
| 割平面     | 收紧 LP 松弛       | 提升下界，使节点可行域逐渐逼近整数可行域的凸包 |
| 启发式算法 | 快速寻找整数可行解 | 改善当前最好可行解，即降低最小化问题的上界     |
| 优化策略   | 调整算力分配方向   | 在找可行解、改善界和证明最优之间选择侧重点     |

## 2. 设置求解终止条件

### 2.1 `TimeLimit`：按实际运行时间终止

当模型无法在可接受时间内找到最优解时，可以使用 `TimeLimit` 限制求解时间。

| 项目                 | 含义                              |
| -------------------- | --------------------------------- |
| 设置方式             | `model.Params.TimeLimit = 秒数`   |
| 限时内求得最优解     | 状态为 `OPTIMAL`，状态码为 `2`    |
| 达到限时但未完成搜索 | 状态为 `TIME_LIMIT`，状态码为 `9` |
| 查询实际运行时间     | `model.Runtime`                   |

实际的 `Runtime` 可能略大于 `TimeLimit`，因为 Gurobi 在停止优化进程时还需要执行额外操作。

在多目标优化中，不能直接用一个 `TimeLimit` 控制每个目标的求解时间，需要为不同目标创建特定设置环境。

#### PDF 示例代码

```python
from gurobipy import *

model = read("input.mps")     # 载入模型
model.Params.TimeLimit = 5    # 设置求解时间为 5s
model.optimize()              # 求解模型
model.Runtime                 # 获取求解时间
```

### 2.2 `WorkLimit`：按确定性工作量终止

使用相同的 `TimeLimit` 和相同的输入数据重复求解，结果仍可能出现微小差异，因为模型不一定在分支切割树的同一节点终止。

`WorkLimit` 使用确定性的最小工作单位控制求解：

- 工作量可以通过 `Work` 属性查询；
- 相同模型使用相同的 `WorkLimit`，能够在相同节点终止并得到相同结果；
- 一个工作单位大致相当于一秒，但实际时长受硬件和模型影响。

| 参数        | 计量基础     | 重复求解特征             | 适用目的         |
| ----------- | ------------ | ------------------------ | ---------------- |
| `TimeLimit` | 实际运行时间 | 可能在不同节点终止       | 控制墙钟时间     |
| `WorkLimit` | 确定性工作量 | 相同模型可在相同节点终止 | 保证实验可重复性 |

### 2.3 `MIPGap`：按相对 Gap 终止

对于最小化问题，记：

- $z_u$：当前最好整数可行解的目标值，即当前上界；
- $z_l$：当前获得的最好下界。

PDF 中给出的 Gap 为：

$$
\mathrm{Gap}=\frac{z_u-z_l}{z_u}\times 100\%.
$$

Gap 越小，当前可行解越接近全局最优解；Gap 为 0 时，当前最好可行解同时为全局最优解。

特殊情况：

- 若 $z_u=z_l=0$，则 Gap 记为 0；
- 若 $z_u=0$ 且 $z_l\ne 0$，则 Gap 记为无穷大；
- PDF 特别说明，按照 Gurobi 的计算方式，Gap 可能取负值，不同求解器的 Gap 定义也可能不同。

| 名称                     | 类别     | 作用                       |
| ------------------------ | -------- | -------------------------- |
| `model.Params.MIPGap`    | 参数     | 设置相对 Gap 终止阈值      |
| `model.Params.MIPGapAbs` | 参数     | 设置上下界绝对差的终止阈值 |
| `model.MIPGap`           | 模型属性 | 求解后查询当前 Gap         |

> 不要混淆：`model.Params.MIPGap` 用于设置终止条件，`model.MIPGap` 用于读取求解结果。

### 2.4 终止条件参数对照表

| 参数             | 描述                                         | PDF 所列类型/单位 |
| ---------------- | -------------------------------------------- | ----------------- |
| `TimeLimit`      | 限制实际运行时间                             | 秒                |
| `WorkLimit`      | 限制确定性工作量                             | 工作单位          |
| `MIPGap`         | 设置相对 Gap 阈值                            | 相对值            |
| `MIPGapAbs`      | 设置上下界绝对差阈值                         | 绝对值            |
| `BarIterLimit`   | 限制 Barrier 算法的迭代次数，默认 1000 次    | `int`             |
| `BestBdStop`     | 当目标函数的最优边界至少与参数值相同时终止   | `double`          |
| `BestObjStop`    | 当目标函数的最优可行解至少与参数值相同时终止 | `double`          |
| `Cutoff`         | 当前最优解等于或优于参数值时终止             | `double`          |
| `IterationLimit` | 限制单纯形迭代次数                           | `double`          |
| `NodeLimit`      | 限制分支切割算法探索的 MIP 节点数            | `double`          |
| `MemLimit`       | 限制求解器可用内存，超过时终止               | `double`，GB      |
| `SolutionLimit`  | 限制需要寻找的 MIP 初始解数量                | `int`             |

## 3. 设置预处理算法

### 3.1 预处理的作用

预处理是 Gurobi 启动求解后的第一个步骤。预处理本身会消耗时间，但它可以：

- 精简模型结构；
- 缩减模型规模；
- 删除冗余约束或变量；
- 改善部分系数范围；
- 使后续模型更容易求解。

### 3.2 预处理参数对照表

| 参数              | 描述                                         | 类型  |
| ----------------- | -------------------------------------------- | ----- |
| `AggFill`         | 控制预处理聚合过程中的填充量                 | `int` |
| `Aggregate`       | 选择预处理算法的聚合策略                     | `int` |
| `DualReductions`  | 是否在预处理中缩减对偶规模                   | `int` |
| `PreCrush`        | 允许将原模型约束转换为预处理后模型的约束     | `int` |
| `PreDepRow`       | 控制依赖行缩减，消除约束矩阵中的线性相关约束 | `int` |
| `PreDual`         | 控制是否生成连续模型的对偶模型               | `int` |
| `PreMIQCPForm`    | 决定 MIQCP 模型预处理后的格式                | `int` |
| `PrePasses`       | 限制预处理的最大迭代次数                     | `int` |
| `PreQLinearize`   | 控制二次矩阵的线性化                         | `int` |
| `Presolve`        | 控制预处理后模型的简化程度                   | `int` |
| `PreSOS1BigM`     | 控制 SOS1 约束是否重构为二次形式             | `int` |
| `PreSOS1Encoding` | 控制 SOS1 约束的重构策略                     | `int` |
| `PreSOS2BigM`     | 控制 SOS2 约束是否重构为二次形式             | `int` |
| `PreSOS2Encoding` | 控制 SOS2 约束的重构策略                     | `int` |
| `PreSparsify`     | 控制约束矩阵中非零项的缩减过程               | `int` |

> 原表 24.2 对 `PrePasses` 的简述为“控制预处理算法的聚合策略”，但本节后文明确说明它用于限制预处理的最大迭代次数。本笔记采用后文的详细说明。

### 3.3 `Presolve` 参数取值

| 取值 | 策略 | 特点                                       |
| ---: | ---- | ------------------------------------------ |
| `-1` | 自动 | 默认值，求解器根据模型复杂度自动选择       |
|  `0` | 关闭 | 不执行预处理                               |
|  `1` | 保守 | 减少预处理投入                             |
|  `2` | 积极 | 尽量生成更紧凑的模型，但预处理耗时可能更长 |

降低 `Presolve` 的积极程度通常会影响后续求解效率，但关闭预处理不一定总会使模型变慢。对于约束系数、右端常数或目标系数最大值与最小值相差很大的模型，关闭预处理有时可以减弱数值问题的影响。

### 3.4 参数、方法与统计接口

| 调用                    | 类别 | 作用                                             |
| ----------------------- | ---- | ------------------------------------------------ |
| `model.Params.Presolve` | 参数 | 设置预处理的积极程度                             |
| `model.presolve()`      | 方法 | 单独执行预处理并返回预处理后的模型               |
| `model.printStats()`    | 方法 | 输出约束数、变量数、非零项数和系数范围等统计信息 |

### 3.5 VRPTW 预处理示例代码

```python
from gurobipy import *

model = read("VRPTW.mps")       # 载入模型
model.printStats()              # 查看原模型统计信息
model.Params.Presolve = 2       # 设置为积极预处理
p = model.presolve()            # 单独执行预处理，返回预处理后的模型
p.printStats()                  # 查看预处理后模型统计信息
```

## 4. 设置割平面算法

### 4.1 割平面的作用

割平面是 Gurobi 分支切割框架的重要组成部分。它通过加入对所有整数可行解都成立的新约束，排除 LP 松弛中的部分分数解，使节点可行域逐渐逼近整数可行域的凸包。

对于最小化问题：

- 启发式算法主要用于寻找更好的整数可行解，降低上界；
- 割平面主要用于收紧 LP 松弛，提高下界；
- 上下界逐渐接近，Gap 随之缩小。

### 4.2 割平面全局参数

| 参数           | 描述                                   | 类型  |
| -------------- | -------------------------------------- | ----- |
| `Cuts`         | 控制所有割平面的生成                   | `int` |
| `CutAggPasses` | 控制割平面生成过程中约束聚合的迭代次数 | `int` |
| `CutPasses`    | 限制根节点中生成割平面的最大迭代次数   | `int` |

### 4.3 具体割平面参数

| 参数              | 控制的割平面                                 | 类型  |
| ----------------- | -------------------------------------------- | ----- |
| `BQPCuts`         | 布尔二次多边形割（BQP cut）                  | `int` |
| `CliqueCuts`      | 团割（Clique cut）                           | `int` |
| `CoverCuts`       | 覆盖割（Cover cut）                          | `int` |
| `FlowCoverCuts`   | 流覆盖割（Flow cover cut）                   | `int` |
| `GUBCoverCuts`    | GUB 覆盖割（GUB cover cut）                  | `int` |
| `GomoryPasses`    | 分数割（Gomory cut）的迭代次数               | `int` |
| `ImpliedCuts`     | 隐界割（Implied bound cut）                  | `int` |
| `InfProofCuts`    | 不可行性证明割（Infeasibility proof cut）    | `int` |
| `LiftProjectCuts` | 提升与投影割（Lift-and-project cut）         | `int` |
| `MIPSepCuts`      | MIP 模型分离割（MIP separation cut）         | `int` |

| `ZeroHalfCuts`    | 零半割（Zero half cut）                      | `int` |

### 4.4 割平面参数的积极程度

| 取值 | 含义             |
| ---: | ---------------- |
| `-1` | 自动调整，默认值 |
|  `0` | 关闭             |
|  `1` | 保守             |
|  `2` | 积极             |

割平面策略越积极，通常会生成更紧的松弛模型，但割的生成和求解也会消耗更多时间。

具体割平面参数会覆盖全局参数 `Cuts` 对相应割的设置。例如：

```python
model.Params.Cuts = -1
model.Params.FlowCoverCuts = 0
```

上述设置表示：总体割平面策略由 Gurobi 自动调整，但关闭流覆盖割；求解器仍可尝试其他割平面算法。

## 5. 设置启发式算法

### 5.1 启发式算法的作用

启发式算法通过牺牲最优性、精确性或完整性的保证换取求解速度，主要用于快速获得可行解或近似解。

Gurobi 的启发式属于数学启发式（Matheuristic），即把数学规划与元启发式相结合，并利用问题结构、LP 松弛解或部分解来加速 MIP 求解。Gurobi 在分支切割树节点处会调用 30 多种内置启发式算法。

在最小化问题中，启发式算法主要用于更快地更新上界并促进 Gap 收敛。

### 5.2 七类启发式算法

| 类别                | 基本思想与特点                                               |
| ------------------- | ------------------------------------------------------------ |
| 独立于 LP 的启发式  | 包括最短路、动态规划、最小生成树、盲目启发式和非松弛启发式；不依赖或不必先求出 LP 松弛解 |
| 基于 LP 的启发式    | 包括基于 LP 的贪婪算法和取整法；多数 Gurobi 启发式依赖 LP 松弛解，直接取整在含等式约束时通常表现较差 |
| 模型改建启发式      | 包括去除目标启发式和最小松弛启发式，通过改变目标或允许约束松弛来寻找可行解 |
| RINS                | 利用节点松弛解的信息固定部分变量，构造并求解规模更小的子模型 |
| SubMIP 与递归启发式 | 固定一定比例的变量，反复传播并求解子 MIP，子 MIP 内还可递归调用启发式 |
| 可行性泵            | 将 LP 分数解取整，构造到整数点的距离目标并重复求解，直至找到可行解 |
| 泵式缩减            | 在可行性泵基础上扩展，针对对偶退化模型寻找整数变量占比更大的松弛解 |

#### 去除目标启发式与最小松弛启发式

- 去除目标启发式：删除原目标函数，把问题转化为较容易求解的约束规划问题，以快速寻找可行解。
- 最小松弛启发式：为约束增加表示违背程度的新变量，把目标改为最小化约束违背总和；若最优总和为 0，则原模型可行并得到一个可行解，否则原模型不可行。

#### RINS 的基本过程

1. 获取当前节点的 LP 松弛解；
2. 利用松弛解与高质量可行解之间的一致信息，固定部分变量；
3. 构造规模远小于原模型的子模型；
4. 求解子模型；
5. 若发现更好的可行解，则传回原模型继续求解。

#### SubMIP 与递归启发式的基本过程

1. 设置变量固定比例的上限；
2. 从第一个变量开始逐个固定并传播；
3. 重复固定与传播，直至模型不可行或达到上限；
4. 将固定变量后的模型作为 SubMIP 求解；
5. 在 SubMIP 中递归调用启发式算法。

### 5.3 启发式算法参数对照表

| 参数             | 描述                                   | 类型     |
| ---------------- | -------------------------------------- | -------- |
| `Heuristics`     | 设置求解过程中启发式算法的大致时间占比 | `double` |
| `ZeroObjNodes`   | 调整去除目标启发式中探索的节点数       | `int`    |
| `MinRelNodes`    | 限制最小松弛启发式中探索的节点数       | `int`    |
| `RINS`           | 调整松弛诱导邻域搜索的频率             | `int`    |
| `SubMIPNodes`    | 限制 SubMIP 与递归启发式探索的节点数   | `int`    |
| `PumpPasses`     | 限制泵式缩减算法的迭代次数             | `int`    |
| `NoRelHeurTime`  | 限制非松弛启发式的总运行时间           | `int`    |
| `NoRelHeurWork`  | 限制非松弛启发式的总计算量             | `double` |
| `NLPHeur`        | 控制非线性内点法启发式                 | `int`    |
| `PartitionPlace` | 控制分割启发式的调用位置               | `int`    |

### 5.4 常用参数说明

#### `Heuristics`

- 全局控制启发式算法的时间投入比例；
- 默认值为 `0.05`，即大约用 5% 的时间执行启发式；
- 设置为 `0` 表示关闭数学启发式；
- 过于激进或过于保守都可能降低整体求解效率。

```python
model.Params.Heuristics = 0.05
```

#### `ZeroObjNodes`

- 只在根节点使用；
- 仅当其他启发式全部失效时调用；
- 原因是去除目标启发式通常耗时较长，且输出解的质量较差。

#### `SubMIPNodes`

- 控制基于 MIP 的启发式（如 RINS）最多探索多少节点；
- 节点数越多，越可能得到更好的可行解，但也会消耗更多时间。

#### `RINS`

- 控制 RINS 的调用频率；
- 提高 RINS 频率，会将搜索侧重点从证明最优转向寻找更好的可行解；
- PDF 建议在调整 RINS 前，优先测试 `MIPFocus`、`ImproveStartGap` 和 `ImproveStartTime`。

#### `NoRelHeurTime` 与 `NoRelHeurWork`

非松弛启发式可以在求解根节点 LP 松弛之前寻找高质量可行解。当根节点 LP 松弛很难求解时，该方法尤其有用。

## 6. 设置优化求解策略

### 6.1 求解策略参数对照表

| 参数                | 描述                                     | PDF 表 24.6 所列类型 |
| ------------------- | ---------------------------------------- | -------------------- |
| `MIPFocus`          | 设置 MIP 求解器的全局求解策略            | `int`                |
| `Method`            | 设置线性模型或 MIP 根节点的求解方法      | `int`                |
| `ImproveStartGap`   | 通过 Gap 阈值切换到提升可行解质量的策略  | `double`             |
| `ImproveStartNodes` | 通过节点数阈值切换到提升可行解质量的策略 | `double`             |
| `ImproveStartTime`  | 通过时间阈值切换到提升可行解质量的策略   | `double`             |
| `BranchDir`         | 设置子节点分支方向偏好                   | `double`             |
| `VarBranch`         | 控制分支变量的选择策略                   | `double`             |

> 表 24.6 将 `BranchDir` 和 `VarBranch` 的类型列为 `double`，但本节后文给出的都是整数编码取值。本笔记保留 PDF 表中的类型，同时按后文记录各整数取值的含义。

### 6.2 `MIPFocus`：设置全局优化侧重点

| 取值 | 求解侧重点                         | 适用现象                     |
| ---: | ---------------------------------- | ---------------------------- |
|  `0` | 在寻找可行解与证明最优之间保持平衡 | 默认设置                     |
|  `1` | 快速寻找可行解                     | 长时间找不到可行解           |
|  `2` | 证明解的最优性                     | 已有较好解，希望充分证明最优 |
|  `3` | 提升界                             | 下界提升缓慢或长时间不更新   |

```python
model.Params.MIPFocus = 1
```

`MIPFocus` 在求解开始前确定全局搜索策略。

### 6.3 `ImproveStart*`：在达到阈值后切换策略

这三个参数不会从求解开始就改变全局侧重点，而是在达到用户设定的进度阈值后，放弃主要进行最优性证明，转而集中算力寻找更好的可行解。

| 参数                | 触发条件                 | PDF 示例                          |
| ------------------- | ------------------------ | --------------------------------- |
| `ImproveStartGap`   | 当前 Gap 收紧至指定阈值  | 设置为 `0.1`，Gap 小于 10% 时切换 |
| `ImproveStartNodes` | 已探索节点数超过指定阈值 | 设置为 `10`，节点数大于 10 时切换 |
| `ImproveStartTime`  | 运行时间超过指定阈值     | 设置为 `10`，运行 10s 后切换      |

```python
model.Params.ImproveStartGap = 0.1
# 或
model.Params.ImproveStartNodes = 10
# 或
model.Params.ImproveStartTime = 10
```

### 6.4 `Method`：加速根节点松弛求解

当 MIP 根节点 LP 松弛求解耗时较长时，可以尝试改变连续优化方法。

|         设置 | 含义           |
| -----------: | -------------- |
| `Method = 2` | 使用并行内点法 |
| `Method = 3` | 使用并发求解器 |

```python
model.Params.Method = 2
```

还可以使用 `NodeMethod` 为其他节点的松弛模型指定方法。不过在大多数情况下，Gurobi 默认使用的对偶单纯形法已经足够高效，改用其他算法带来的提升往往不显著。

如果调整 `Method` 后根节点松弛仍然很难求解，可以尝试用 `NoRelHeurTime` 或 `NoRelHeurWork` 控制非松弛启发式，在求解根节点松弛前搜索可行解。

### 6.5 `BranchDir`：设置分支方向偏好

| 取值 | 分支方向                      |
| ---: | ----------------------------- |
|  `0` | 自动选择，默认值              |
| `-1` | 优先探索下分支（Down Branch） |
|  `1` | 优先探索上分支（Up Branch）   |

### 6.6 `VarBranch`：选择分支变量的策略

| 取值 | 变量选择策略                                      |
| ---: | ------------------------------------------------- |
| `-1` | 自动设置，默认值                                  |
|  `0` | 伪检验数分支（Pseudo Reduced Cost Branching）     |
|  `1` | 伪影子价格分支（Pseudo Shadow Price Branching）   |
|  `2` | 最大不可行分支（Maximum Infeasibility Branching） |
|  `3` | 强分支（Strong Branching）                        |

### 6.7 `VarBranch` 与 `BranchPriority` 的区别

| 名称                      | 类别           | 控制层次                     |
| ------------------------- | -------------- | ---------------------------- |
| `model.Params.VarBranch`  | 模型参数       | 设置整体的分支变量选择模式   |
| `variable.BranchPriority` | `Var` 对象属性 | 为某个具体变量指定分支优先级 |

如果对模型中某些变量的重要性有可靠的先验知识，提高这些变量的 `BranchPriority`，可能提高其在分支切割算法中的分支频率并改善求解效率。

## 7. 常见求解现象与参数选择

| 求解现象或目标                 | 优先考虑的参数                             | 调整思路                                       |
| ------------------------------ | ------------------------------------------ | ---------------------------------------------- |
| 只允许求解固定秒数             | `TimeLimit`                                | 到达墙钟时间后终止                             |
| 希望多次实验在同一节点终止     | `WorkLimit`                                | 使用确定性工作量代替时间                       |
| 只要求达到一定相对误差         | `MIPGap`                                   | 设置可接受的相对 Gap                           |
| 只要求上下界绝对差足够小       | `MIPGapAbs`                                | 设置绝对 Gap 阈值                              |
| 预处理时间过长                 | `Presolve`、`PrePasses`                    | 尝试保守预处理或限制迭代次数                   |
| 模型系数跨度大、存在数值问题   | `Presolve`                                 | 对比自动、保守或关闭预处理的效果               |
| 长时间找不到可行解             | `MIPFocus = 1`、`Heuristics`               | 把更多精力投入寻找可行解                       |
| 已有解，但下界长期不提升       | `MIPFocus = 3`、`Cuts`                     | 加强界的提升和割平面策略                       |
| 希望重点证明最优               | `MIPFocus = 2`                             | 将搜索重点放在最优性证明上                     |
| Gap 已较小，希望继续改善可行解 | `ImproveStartGap`                          | 达到阈值后切换到改善解的策略                   |
| 根节点 LP 松弛耗时很长         | `Method`、`NoRelHeurTime`、`NoRelHeurWork` | 尝试并行内点法、并发求解器或先运行非松弛启发式 |
| 对重要分支变量有先验知识       | `BranchPriority`                           | 提高特定变量的分支优先级                       |

> 本章反复强调：不存在对所有模型都最好的固定参数组合。更积极的预处理、割平面或启发式都会带来额外计算成本，需要针对具体模型进行调优和对照实验。

## 8. 参数、属性和方法速查

| 写法                  | 类别     | 何时使用                 | 示例                                   |
| --------------------- | -------- | ------------------------ | -------------------------------------- |
| `model.Params.参数名` | 参数     | 优化前设置求解行为       | `model.Params.TimeLimit = 5`           |
| `model.属性名`        | 模型属性 | 优化后读取结果或状态     | `model.Runtime`、`model.MIPGap`        |
| `model.方法名()`      | 方法     | 让模型执行某项操作       | `model.optimize()`、`model.presolve()` |
| `variable.属性名`     | 变量属性 | 控制或读取单个变量的信息 | `variable.BranchPriority`              |

本章最容易混淆的三组写法：

```python
# 参数：设置允许求解的时间
model.Params.TimeLimit = 5

# 属性：读取实际求解时间
runtime = model.Runtime

# 参数：设置预处理策略
model.Params.Presolve = 2

# 方法：单独执行预处理
presolved_model = model.presolve()

# 参数：设置终止 Gap
model.Params.MIPGap = 0.01

# 属性：读取当前 Gap
gap = model.MIPGap
```

## 9. 本章总结

1. `TimeLimit` 控制实际时间，`WorkLimit` 控制确定性工作量；需要实验可重复性时优先考虑后者。
2. `MIPGap` 和 `MIPGapAbs` 分别以相对差和绝对差控制提前终止。
3. 预处理通过缩减行列和调整模型结构降低求解难度，但预处理越积极不一定总是越快。
4. 对最小化问题，割平面通过收紧 LP 松弛提高下界，启发式通过寻找更好可行解降低上界。
5. `MIPFocus` 决定全局侧重点，`ImproveStart*` 在达到指定进度后才切换到改善可行解的策略。
6. 根节点 LP 难求时可测试 `Method`，也可以在 LP 松弛前使用非松弛启发式。
7. `VarBranch` 控制整体分支变量选择模式，`BranchPriority` 控制具体变量的分支优先级。
8. 参数调优必须结合模型和日志进行，不应假设某一组参数对所有问题都有效。
