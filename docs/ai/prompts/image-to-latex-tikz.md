# 图片转 LaTeX/TikZ｜学术技术图可编辑复刻

这套 Prompt 用于将已有的技术图片转成可编辑、可重新编译的 XeLaTeX + TikZ 源码，适合把 Work 生成的技术图、课程示意图或已有算法流程图交给 Codex 复刻。目标是保留参考图的内容、结构和视觉层级，不重新设计或扩展技术内容。

如果需要从文字、代码和公式重新组织并绘制技术图，可使用[纸间代码｜小红书 LaTeX 学术技术绘图](./xiaohongshu-latex-technical-diagram)。本页以已有图片为主要参照，原图采用不同视觉设计时，不强制套用 Paper Code Academic Blue。

## 使用方式 {#usage}

1. 复制下面的完整 Prompt，并附上页面末尾填写好的任务模板。
2. 上传一张或多张参考图片，注明顺序；有原始代码、公式或说明时一并提供。
3. 填写已有工程和共享样式路径，便于复用；没有时写“无”。
4. 执行复刻后，按参考图逐页核对源码、PDF 和 PNG，而不只检查编译是否成功。

优先级：**技术内容准确性 > 结构与连接关系正确 > 公式和文字可编辑 > 视觉一致性 > 像素级还原。**

## 完整 Prompt {#complete-prompt}

复制整个代码块即可使用，站点现有的代码块复制按钮会保留命令和工程结构。模板区分技术准确性与执行次数限制：每图最多 2 轮编译错误修复，全部图片最多 1 轮集中视觉修复；未解决的问题须如实报告。

```text
你是一名 LaTeX/TikZ 学术技术绘图工程师。请将我提供的一张或多张技术图片忠实复刻为可编辑、可重新编译的 XeLaTeX + TikZ 工程。

一、核心目标与优先级

保留原图的技术内容、文字、公式、矩阵、模块布局与连接关系，不重新设计、增删计算步骤或扩展技术内容。
优先级：技术内容准确性 > 结构与连接关系正确 > 原生可编辑 > 视觉一致性 > 像素级还原。
技术准确性是交付标准；下文次数限制只约束单次自动执行，不能据此忽略错误或将未解决问题标为通过。

二、参考图与技术核对

- 按用户指定顺序编号，只分析当前图片涉及的内容；识别页面比例、分区、元素和连接关系，不输出冗长的元素清单。
- 结合用户提供的代码、公式和说明，核对数学符号、上下标、转置、矩阵行列、张量维度及计算逻辑。涉及 PyTorch 时，核对函数与参数、轴变换、Batch/特征维度、权重与偏置形状、广播和执行顺序。
- 依据可见连线和技术材料确认箭头起止、方向、分支与合流，不凭模块位置推断计算顺序，不把分组边界当作流程终点。
- 内容模糊、材料冲突或发现技术错误时，只列出图号、位置、疑点与核对依据，提出最少的必要澄清；可继续已确认部分。不得猜测参数、数值或公式，不静默纠正；技术修正须经用户确认，未确认部分标为待确认。

三、视觉复刻与样式复用

- 保留原图方向、页面比例、模块顺序与层级，不擅自合并、拆分模块或将一张图拆成多页。未指定尺寸时按原图比例设定画布，不拉伸内容。
- 尽量还原字体类别与粗细、字号层级、配色、圆角、边框、箭头、留白和对齐。仅在用户允许少量排版优化时微调间距或对齐，并说明偏差。
- 优先复用已有 Paper Code Academic Blue 共享样式；与原图冲突时以原图为准，仅在当前工程中局部适配。未提供样式时，集中定义必要样式，不创建多套模板或编造依赖路径。
- 精确字体不可用时选择最接近的开源字体，说明替代及可见影响；无法识别原字体时如实标注，不声称准确使用了原字体。

四、原生可编辑实现

- 文字、公式、矩阵、边框和箭头均使用原生 LaTeX/TikZ；禁止整图嵌入替代复刻，或将文字、公式截图伪装成可编辑内容。确实无法原生还原的元素单独报告限制。
- 使用 amsmath、amssymb 与标准数学环境排版公式；代码使用等宽字体并转义特殊字符，保留名称和大小写，数学变量按数学语义排版。
- 矩阵与表格使用 TikZ matrix 或 LaTeX 表格，保留行列、合并关系及单元格内容。节点使用有意义的名称，优先采用 positioning、锚点和 calc；必要的固定坐标、尺寸与间距集中定义。
- 连接线通过节点锚点连接，避开文字和公式，保留跨模块、跨分组路径。分组框置于背景层，交叉处只调整分组边界，不截断流程线、不增加额外箭头，也不改变计算关系来消除交叉。

五、工程结构与文件组织

先检查并复用已有项目、主入口、共享样式及用户修改。无现有工程时采用以下结构（以两张图为例）：

latex/
├── main.tex
├── paper-code-style.tex
├── figures/
│   ├── 01_figure.tex
│   └── 02_figure.tex
├── .build/
└── output/
    ├── main.pdf
    ├── 01_figure.png
    └── 02_figure.png

- 源码采用 UTF-8 和工程内相对路径，交付编译所需资源，不依赖个人绝对路径。
- main.tex 为统一编译入口，声明文档、加载共享样式一次，并按图序引入子图及显式分页；figures/ 下每图一份源码，只含绘图主体，不重复声明文档。
- 默认每张参考图对应 PDF 一页和一张 PNG；单图沿用同一结构。不同方向或尺寸在主入口中逐页处理。只有用户明确要求时才设独立编译入口，并继续复用共享样式。

六、执行流程与次数限制

本节上限适用于单次自动执行；达到上限即停止相应修复并报告，不能以更换工具、拆分步骤或重启流程重置计数。
一轮修复指：针对已发现的问题集中修改一次，再统一编译并检查结果；视觉修复还包括重新导出受影响页面并查看。

1. 先完成全部图片的初版源码，再统一编译主入口；不分别编译子图，也不先反复打磨单张图。
2. 每张图最多进行 2 轮编译错误修复，初次编译不计入。共享文件错误计入所有受影响图片；视觉修复阶段发生的编译错误也共用此额度。
3. 初版成功编译后，逐页查看并汇总问题，全部图片最多进行 1 轮集中视觉修复。只修复内容遗漏、明显布局偏差、公式显示异常、裁切、重叠或箭头连接问题；涉及技术含义时仍须先确认。修复后仅验证结果，不开启第二轮视觉调整。
4. 同一问题连续两次修复仍未解决，立即停止对该问题的重试并报告；若阻断统一编译或导出，说明受影响的交付物，不宣称完成。
5. 不为细微的像素、字体或间距差异反复修改；无法消除的偏差如实列出。
6. 不重新生成已完成且无需修复的源码或 PNG，不修改无关文件。统一主入口需要重编译整份 PDF 时，保留已完成源码，仅更新受影响 PNG，确保其与最终 PDF 对应；共享样式变更须复查所有受影响页面。
7. 不启动额外的审查代理，不执行与当前图片无关的检查，不自动提交、推送或部署。

七、编译与质量验收

在工程目录中确认 .build/ 和 output/ 存在，通过统一主入口执行：
xelatex -interaction=nonstopmode -halt-on-error -file-line-error -output-directory=.build main.tex
整个执行过程中，仅在日志明确提示需重跑以稳定引用或节点定位时，最多追加 1 次无源码修改的编译；仍未稳定则报告。修复后的编译遵守第六节额度。

- 检查编译错误、缺失字体、中文乱码及公式显示；Overfull/Underfull 警告仅处理实际影响内容的问题。缺少编译器、字体或渲染工具时，报告缺失项和未完成检查，不盲目重复执行。
- 核对 PDF 页数、页序与参考图对应，逐页尺寸符合原图比例或用户指定要求，无漏页、重复页或空白页；画面越界可能没有日志警告，须查看输出。
- 初版编译成功后，从 .build/main.pdf 导出全部 PNG 供视觉对照，长边建议不低于 2400px；修复后仅重新导出受影响页，确保交付 PNG 与最终 PDF 一致。首次导出命令如下，指定页时加 -f/-l：
  pdftoppm -png -scale-to 2400 .build/main.pdf .build/main
- 将 PDF 交付为 output/main.pdf，PNG 按图序命名为 01_figure.png 等，核对图号、源码、PDF 页码与 PNG 的映射。
- 对照参考图逐页查看公式与矩阵、文字与代码、模块布局、裁切与重叠、箭头起止及跨分组连接，并检查配色、边框和页面比例。编译成功不等于视觉通过；未实际查看的页面不得声称已验收。

八、最终报告

简要列出：
1. 源码与资源路径、统一编译入口和可运行命令，以及各图源码、PDF 页码、PNG 的对应关系。
2. 实际编译、导出及视觉检查结果，已用修复轮次与未完成的交付物或检查。
3. 待确认项、剩余问题及停止原因；经确认的技术修正与依据单独说明。
4. 字体替代、允许的排版调整及无法还原元素的处理方式与可编辑性限制。
```
